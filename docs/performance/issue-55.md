# Issue #55: 名前の幅計測と結果の再利用

2026-10-20 JST。比較元は #54 を適用した `5061ccb`、比較先は本 PR の実装。#54 で削減済みの切替時の計測を、今回の追加効果に数えない。

## 実装

- 各 OverlayName が最大8件の調整結果を保持する。名前、実際の内容領域の幅、タグ、基準サイズ、実効 font family・weight・style・文字間隔などをキーにする。ヒットした組合せを新しい順へ移し、上限を超えた古い組合せを捨てる。共有の無制限なキャッシュは持たず、アンマウントで解放される。
- 初回計測後の ResizeObserver 通知は、その内容領域の幅を直接使う。同じ条件なら書込み・名前の幅読取りを行わない。幅を戻した場合も結果を再利用する。
- 未計測の条件では基準サイズの実測から比例縮小し、2点の実測値から得た傾きで補正する。固定 px の文字間隔を含む名前でも少数回で範囲を絞り、従来と同じ 1/4096 刻みの最大サイズを選ぶ。
- 比例予測・補正・近傍確認の後に残った区間では、最大12回の二分探索を残す。すべてのフォントで同じ回数削減を保証するものではない。
- 名前・タグ・className の変更、内容領域の幅変更で再評価し、フォント読込み完了時には保持した結果を破棄して実測し直す。Canvas 計測や省略記号は導入していない。

## 完了条件の確認

- 既存のプレイヤー名・チーム名の4件に加え、`name-fit-cache.spec.ts` で日本語・英数字・絵文字の混在、存在しない font family からのフォールバックを全20要素で確認。
- 幅変更・幅の復元、同幅通知の再送、同じ要素での名前変更、font family・weight・基準サイズ変更を検証。
- 同じ font family のフォールバック結果を先にキャッシュし、その後に FontFace を実際に読み込んで再計測されることを確認。
- 12種類の幅を順に使用し、上限を超えた古い幅へ戻すと再計測することを確認。コード上の上限は要素ごとに8件。
- 追加したサイズ比較の回帰テストで、全20要素の最終サイズが旧12回探索と一致することを確認。既存の視覚比較画像は更新しない。
- Web build・lint・spellcheck と差分チェックを実施。Chrome の結果と、未確認の OBS/CEF 実機を区別する。
